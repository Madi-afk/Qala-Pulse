# Развёртывание

Compose по умолчанию предназначен для локальной разработки. БД, Redis и MinIO публикуются только на loopback портах 55432, 16379, 59000/59001. Внешний порт Redis меняется через `REDIS_BIND_PORT`; внутренний остаётся 6379. Старый 56379 может попадать в зарезервированные Windows диапазоны (`netsh interface ipv4 show excludedportrange protocol=tcp`). При запуске Python вне Docker согласуйте `REDIS_URL` с внешним портом. Backend слушает 8000 для физического телефона в доверенной локальной сети. В пилоте ограничьте доступ сетевым экраном и поставьте HTTPS reverse proxy.

`scripts/setup_env.py` создаёт случайные пароли и JWT-секрет, не меняя существующий `.env`. Файл хранится вне Git. Бакеты создаёт одноразовый minio-init; оба имеют anonymous policy none. Ошибка любой команды инициализации завершает сервис неуспешно; ожидание MinIO ограничено 120 сек.

## MinIO: сборка из официальных исходников

Во время проверки 29.09.2026 старые образы Quay и проверенные release-теги Docker Hub возвращали unauthorized/denied. Вместо зависимости от их доступности Compose собирает **локальные образы проекта**, не выдавая их за опубликованные официальные images:

| Компонент | Официальный release | Закреплённый commit |
|---|---|---|
| minio | [RELEASE.2025-04-22T22-12-26Z](https://github.com/minio/minio/tree/RELEASE.2025-04-22T22-12-26Z) | `0d7408fc9969caf07de6a8c3a84f9fbb10a6739e` |
| mc | [RELEASE.2025-08-13T08-35-41Z](https://github.com/minio/mc/tree/RELEASE.2025-08-13T08-35-41Z) | `7394ce0dd2a80935aded936b09fa12cbb3cb8096` |

`infrastructure/minio/Dockerfile` проверяет SHA checkout, собирает CGO-free бинарник и включает upstream LICENSE (AGPL-3.0) и OCI source/revision labels. Исходники и зависимости сохраняют свои лицензии; MIT проекта их не заменяет. Upstream go.sum проверяет Go-модули. Это совместимость с выбранным MVP-релизом, не заявление об отсутствии известных уязвимостей.

Базы, для которых локально выполнен успешный настоящий pull:

```bash
docker pull golang:1.24.2-bookworm@sha256:79390b5e5af9ee6e7b1173ee3eac7fadf6751a545297672916b59bfa0ecf6f71
docker pull alpine:3.21.3@sha256:a8560b36e8b8210634f77d9f7f9efd7ffa463e380b75e2e74aff4511df3ef88c
```

`docker compose up --build` выполняет сборку автоматически. Первая сборка требует GitHub, Go module proxy и Alpine registry, занимает несколько минут. Исходники и базовые образы закреплены; установка ca-certificates из Alpine всё ещё зависит от package mirror. Для изолированного пилота заранее соберите/проверьте образы и перенесите их в собственный registry. Build cache ускоряет повтор; реальный integration CI собирает всё с чистого runner.

## Проверка без изменения существующей БД

Из корня: `python scripts/run_integration.py` (Python 3.13 с backend dev dependencies и Docker Compose 2.24.4+). Генерируются случайные секреты в игнорируемом временном файле и отдельный project `qalapulse-check-<random>`. Скрипт не читает `.env`, не использует существующие volumes, применяет `0001 → 0002`, создаёт synthetic seed и выполняет четыре интеграционных теста. В `finally` удаляются только его containers/volumes и временный env-файл. Если процесс принудительно убит извне, оставшийся контур определяется по напечатанному уникальному project name; не применяйте очистку к обычному `qalapulse`.

`0002` сохраняет старые подтверждения в цикле 0; обращения с pending/resolved получают текущий цикл 1. Downgrade откажется удалять новую историю или запреты публикации. Проверка миграции сделана только на синтетических данных. Обновление реального контура требует отдельной процедуры с backup/restore; в этом этапе оно не выполнялось.

Для production: уникальные секреты; `ENVIRONMENT=production`; HTTPS; ограниченный CORS; закрытые служебные порты; отдельный MinIO service account с минимальными правами (локальный Compose использует root-учётную запись); мониторинг диска/очереди; регулярные backup/restore. Проверьте поддерживаемость и уязвимости закреплённых образов перед развёртыванием. Не публикуйте консоль MinIO в интернет.

Backup: `pg_dump` из контейнера PostgreSQL в защищённый файл и `mc mirror` обоих бакетов в закрытое резервное хранилище. Ключи записей БД и файлов должны восстанавливаться согласованно. Redis persistence включён для очереди. Не считайте наличие volume резервной копией.

Команда `docker compose down` сохраняет volumes. `down -v` удаляет данные и не нужна для обычного обновления. Миграции запускаются backend до открытия API. Worker стартует после успешной readiness backend.
