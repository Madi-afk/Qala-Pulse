# Хранение фотографий и аудио в пилоте

Предлагаемая техническая политика для утверждения владельцем. Это не юридическое заключение. До реальных данных определить оператора, контакт поддержки и место хранения.

| Данные | Срок от загрузки | Действие |
|---|---|---|
| Оригинал фото | 7 дней | Удаляется из приватного bucket; для нового AI-анализа нужна повторная загрузка |
| Аудио и отдельный транскрипт загрузки | 2 дня | Удаляются; текст, включённый жителем в обращение, остаётся текстом обращения |
| Неприкреплённые фото и thumbnail | 7 дней | Удаляются; старый черновик сохраняется, но файл нужно загрузить заново |
| Публичная обработанная версия и thumbnail | 90 дней | Удаляются независимо от статуса проблемы; текст и история остаются |
| Файлы, оставшиеся после аварии до записи в БД | 7 дней | Удаляются, если ни один Upload на них не ссылается |
| Зашифрованный backup | Окно 30 дней | Старые снимки удаляются через prune при ежедневном backup |
| Запись истёкшего сброса пароля | Сутки после истечения | Хеш удаляется задачей очистки |

Настройки: `ORIGINAL_RETENTION_DAYS`, `AUDIO_RETENTION_DAYS`, `UNATTACHED_RETENTION_DAYS`, `PUBLIC_PHOTO_RETENTION_DAYS`. Возраст отсчитывается от загрузки; закрытие проблемы не продлевает срок. Изменения политики сообщать участникам.

Задача запускается раз в час, до 500 загрузок за проход. Большой backlog требует повторного запуска. Dry-run не удаляет файлы:

```bash
docker compose --env-file .env.pilot -f docker-compose.pilot.yml exec backend python -m app.retention
sudo python3 scripts/pilot_ops.py retention
```

Оригиналы и обработанные версии находятся в разных приватных buckets. API публикует только обработанные фото. После истечения ссылка исключается из списка медиа. Удаление оригинала не мешает просмотру сохранённой обработанной версии.

## Досрочное удаление

Житель обращается по контакту поддержки из паспорта пилота. Модератор скрывает спорный контент и передаёт запрос оператору. Скрытие не удаляет файл.

После проверки основания оператор записывает UUID загрузки, дату и причину в защищённый журнал удаления **вне восстанавливаемого снимка**, без самого фото. Затем проверяет и применяет удаление:

```bash
docker compose --env-file .env.pilot -f docker-compose.pilot.yml exec backend python -m app.retention --erase-upload UPLOAD_UUID
docker compose --env-file .env.pilot -f docker-compose.pilot.yml exec backend python -m app.retention --erase-upload UPLOAD_UUID --apply
```

Удаляются оригинал, redacted, thumbnail, анализ и транскрипт конкретной загрузки. Остаются аудит и техническая запись истечения. Аккаунт, текст обращения и копии на устройствах жителей требуют отдельного рассмотрения; эта команда их не удаляет.

В backup файл может оставаться до окончания окна копий, а при неисправном расписании — дольше. После восстановления старого снимка до открытия сервиса обязательно повторить журнал досрочных удалений и очистку по текущим срокам. Ранее скачанные файлы и черновики на чужих устройствах сервер отозвать не может.

## Ограничения

Детектор лиц и номеров может пропускать объекты. Нужен ручной предпросмотр; при пропуске — полное размытие или другой кадр. В первой тестовой группе модератор дополнительно проверяет каждое фото. Не заявляется автоматическая анонимизация со 100% точностью.

Restic шифрует backup. Диски MinIO этой конфигурацией автоматически не шифруются — включить шифрование диска сервера. Доступ к оригиналам имеет оператор инфраструктуры. Cloud AI по умолчанию выключен; включение требует отдельного информирования и проверки условий передачи данных.
