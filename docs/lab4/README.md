# QalaPulse — Laboratory Work №4

Wireframes Improvement and Interactive Elements. Продолжение существующего проекта QalaPulse.

## Открыть готовый локальный комплект

Откройте `index.html` двойным щелчком. Доступны вкладки:

- **Прототип** — кликабельный сценарий, формы, проверка AI и локальный черновик.
- **15 экранов + 5 модалей** — полный набор wireframes.
- **User Flow** — пять связанных пользовательских сценариев.
- **Состояния** — Default, Hover, Pressed, Disabled, Loading, ошибка, успех, offline.
- **Отчёт** — описание работы для защиты.

Если браузер ограничивает сохранение при `file://`, из корня репозитория:

```powershell
python -m http.server 8764 --bind 127.0.0.1 --directory docs/lab4
```

Откройте http://127.0.0.1:8764/index.html. Исходники и готовый плагин находятся в этой папке; ZIP не хранится в Git. Для сборки архива выполните `python scripts/build_lab4.py` из корня проекта.

## Перенос в Figma — необходим перед сдачей

Задание требует файл Figma. HTML служит дополнительной демонстрацией и не заменяет это требование.

[Созданный файл Figma](https://www.figma.com/design/ssVUpA2oBR5BC8Eqt46oTP) содержит только первоначальную основу: коннектор остановился из-за лимита Starter до заполнения экранов. Не сдавайте эту основу как завершённую работу.

Подготовлен локальный плагин, который генерирует редактируемые элементы Figma:

1. Откройте Figma Desktop и файл с правом редактирования (можно новый файл в Drafts).
2. Выберите **Plugins → Development → Import plugin from manifest…** и файл `figma-plugin/manifest.json` из этого комплекта.
3. Запустите **Plugins → Development → QalaPulse — Laboratory Work 4 → Создать макеты**.
4. Плагин создаст страницу **Lab 4 · Final wireframes**: User Flow, 15 экранов, дополнительное состояние 11b с проверенным AI, 5 модалей и компоненты.
5. Выделите экран **01 · Главная**, откройте **Present**. Проверьте основной путь и окна. Затем скопируйте ссылку на файл для преподавателя; доступ к нему настройте самостоятельно.

Если Figma запросит зарегистрированный ID плагина: создайте **Development → New plugin → Figma design → Run once**, сохраните выданный Figma `id` в нашем manifest и импортируйте его снова. Назначение ID описано в [официальной документации manifest](https://developers.figma.com/docs/plugins/manifest/). Порядок импорта — в [инструкции Figma](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-plugin-for-development).

Плагин не обращается к сети. Повторный запуск показывает готовую страницу целиком. Если предыдущая попытка не завершилась, её страница сохраняется с датой в названии, а генерация выполняется на новой странице; элементы предыдущей попытки не удаляются. Используется Noto Sans, при недоступности — Inter.

**Статус проверки:** JavaScript и структура генератора проверены локально; запуск и визуальный результат внутри Figma ещё не проверены. HTML проверен в браузере. Это различие существенно: структурный тест не эмулирует движок вёрстки Figma.

### Добавить связи к уже созданным экранам

Откройте страницу с заполненными макетами и запустите **Plugins → Development → QalaPulse — Laboratory Work 4 → Связать существующие экраны**. Если новая команда не появилась, повторно импортируйте `figma-plugin/manifest.json` из папки проекта.

Команда сопоставляет экраны 01–15 и M1–M5 по именам, проверяет наличие кнопок, добавляет переходы, открытие/закрытие модалей, возврат и две стартовые точки прототипа. Состояние 11b создаётся только при отсутствии. Повторный запуск не дублирует связи. Если экраны ещё пустые, команда сообщит об этом до изменения переходов. Имена экранов и кнопок должны соответствовать этому комплекту.

После выполнения выберите **01 · Главная → Present (▶)**. Для просмотра линий связей используйте вкладку **Prototype**.

Запрос на изменение файла `d7aQG04h2LnjJqXm6lqEnx` через подключённый Figma MCP отклонён из-за отсутствия edit access. Поэтому обновлена локальная команда; применение к этому облачному файлу пока не подтверждено.

## Состав экранов

| ID | Экран / состояние |
|---|---|
| 01 | Главная: рядом, высокий приоритет, создание |
| 02 | Карта: поиск, категории, фильтры |
| 03 | Обращение: статус, подтверждения, история, комментарии |
| 04 | Вход |
| 05 | Регистрация |
| 06 | Фото ещё не выбрано; Continue disabled |
| 07 | Фото добавлено |
| 08 | Геолокация: GPS и ручная точка |
| 09 | Текст / состояния голосовой записи |
| 10 | AI: loading и ручное заполнение |
| 11 | Проверка и редактирование AI |
| 12 | Дубликаты: подтвердить или создать отдельное |
| 13 | Успешная публикация |
| 14 | События / уведомления |
| 15 | Профиль, язык, черновик, мои обращения |

Модали: **M1** источник фото; **M2** фильтры; **M3** подтверждение публикации; **M4** оценка решения; **M5** ошибка сети и сохранённый черновик.

## Что показать на защите

1. Главная → создать → пустое фото: продолжение заблокировано.
2. Добавить → галерея → геолокация → текст/голос → анализ.
3. AI loading → проверка. Отметить проверку, изменить заголовок: отметка сбрасывается.
4. Проверить снова → дубликаты → создать новое → модаль публикации → успех.
5. Открыть обращение → подтвердить дважды: счётчик увеличится только один раз.
6. Карта → фильтры → «Мусор»: пример пустого результата; сбросить фильтры.
7. На дубликатах открыть ошибку сети → продолжить позже → профиль → черновик. Поля сохраняются после перезагрузки.
8. Показать вкладки User Flow, состояния и все макеты.

## Границы учебной модели

- Это low-fidelity wireframes, не новая версия Flutter-приложения.
- Фото, координаты, голос, AI, авторизация и публикация имитируются; реальных разрешений устройства и сетевых запросов нет.
- В Figma поля предзаполнены, фильтры представлены структурой меню; ввод, поиск и валидация работают в HTML. Радиус и язык показывают выбор, но не выполняют геопоиск и перевод всех экранов.
- В HTML сохраняются только учебные поля черновика. Email, имя и пароль исключены из localStorage. Не вводите настоящие данные.
- Макет русскоязычный. Выбор казахского показывает расположение настройки, а не переводит весь учебный комплект.
- Статусы описывают гражданскую платформу. Отправка государственным органам не имитируется.
- Оригинальные wireframes предыдущих лабораторных не были приложены: основой служит существующее приложение. Сравнение с предыдущим файлом Figma не проводилось.

## Воспроизводимость

Источники: `spec.json`, `styles.css`, `prototype.js`, `figma-plugin/runtime.js`.

```powershell
python scripts/build_lab4.py
node --check docs/lab4/prototype.js
node --check docs/lab4/figma-plugin/code.js
node docs/lab4/check-plugin.cjs
```

Генератор проверяет количество экранов/модалей и цели переходов, собирает HTML, плагин и ZIP. Шрифт из проекта распространяется вместе с `assets/OFL.txt`.
