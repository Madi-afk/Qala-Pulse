# Панель модератора и организации

Панель: **http://localhost:8000/console/**. Она входит в backend и использует настоящие API и базу данных. Отдельный frontend-сервер, Node.js и сборка JavaScript для запуска не нужны.

## Запуск и обновление

С настроенным `.env` и запущенным Docker Desktop, из корня:

```bash
docker compose up -d --build --wait backend worker
docker compose exec backend python -m app.seed
```

Seed нужен только для демонстрационного окружения: создаёт тестовые аккаунты, организацию, 28 синтетических обращений и три жалобы. Уже существующие записи не перезаписывает; в production запуск запрещён.

Compose автоматически выполняет `alembic upgrade head` перед запуском API. Новая миграция `0003` расширяет `incident_media.media_type` с 10 до 20 символов: значение `after_image` ранее не помещалось в PostgreSQL. При локальном запуске без Compose выполните миграцию вручную. Обратная миграция отказывается сужать поле, если есть длинные значения, чтобы не обрезать данные.

| Роль | Тестовый email |
|---|---|
| Модератор | `moderator@qalapulse.example.com` |
| Организация | `organization@qalapulse.example.com` |
| Администратор | `admin@qalapulse.example.com` |

Только для демо: пароль **`QalaPulse-Demo-2026!`**. В рабочем окружении учётные записи и организации предоставляет администратор; роль citizen не получает доступ к панели.

## Рабочий сценарий

1. Модератор входит и фильтрует очередь по тексту/адресу, категории, статусу, видимости или отсутствию назначения. Доступны сортировка по приоритету/дате и страницы.
2. Открывает карточку: обработанные фото, адрес и координаты, опасность, объяснение приоритета, ответственный и срок.
3. Во вкладке «Действия» проверяет категорию, переводит обращение на проверку или отклоняет его. При необходимости скрывает публикацию с подтверждением.
4. Во вкладке «Дубликаты» сравнивает кандидатов. Объединение требует явного подтверждения: исходное обращение скрывается, выбранное остаётся основным. Комментарии и подтверждения не переносятся и не суммируются.
5. Назначает организацию, имя исполнителя/бригады и срок. Поиск организаций поддерживает дополнительные страницы.
6. Организация входит в «Мои назначения», уточняет исполнителя и переводит обращение последовательно: принято → в работе → отмечено как решённое. Окончательное подтверждение остаётся жителям.
7. Организация публикует ответ. Он виден в комментариях мобильного приложения; история содержит событие ответа. Длинный ответ целиком хранится в комментарии, в истории — первые 950 символов.
8. Загружает фото результата, получает обработанный предпросмотр, проверяет его и подтверждает отсутствие личных данных. При необходимости использует «Размыть целиком». После публикации фото видно в карточке и публичном обращении.
9. В разделе жалоб модератор видит причину и конкретное содержимое: обращение либо комментарий. «Скрыть содержимое» действует на объект жалобы; «Отклонить жалобу» закрывает её без скрытия. Оба действия требуют подтверждения. Есть просмотр ранее рассмотренных жалоб.

Каждая форма показывает ожидание, успех или ошибку. Сбой сети оставляет введённый текст в открытой форме. При неизвестном исходе операции сначала обновите карточку; автоматического повтора изменяющих запросов после сетевой ошибки нет.

При смене статуса, категории или видимости панель проверяет версию карточки через `expected_updated_at`. Устаревшая форма получает конфликт вместо перезаписи более свежего изменения другого оператора.

## Архитектура и доступ

- `backend/app/console/`: обычные ES-модули, HTML и CSS. `client.js` отвечает за сессию, `ui.js` — общие элементы, `app.js` — очереди и карточку. Цвета согласованы с Flutter.
- FastAPI отдаёт статику с `/console/` и API с того же origin. Все файлы включены в Python-пакет и Docker-образ.
- `operations.py` и `repositories/operations.py` добавляют ограниченные служебные чтения и ответы. Основные изменения выполняются через существующий `moderation.py`.
- Разрешения проверяет backend при каждом чтении и изменении. Скрытая кнопка не является механизмом защиты. Организация не может назначить себе чужое обращение, сменить его категорию, объединить дубликаты или решить жалобу.
- Служебные фотографии выдаются с Bearer-авторизацией и показываются через временные blob URL. Оригиналы не возвращаются. Публичные маршруты сохраняют прежние проверки видимости.
- Access и refresh tokens находятся только в памяти вкладки, без LocalStorage/SessionStorage и URL. Refresh выполняется одним общим запросом для одновременных 401. Перезагрузка требует повторного входа; logout отзывает refresh и очищает локальную сессию.
- CSP запрещает внешние скрипты и встраивание панели. Пользовательский текст вставляется как текстовые DOM-узлы. Для рабочего развёртывания используйте HTTPS.
- Статусы, назначения, ответы, фото, объединения и решения жалоб оставляют аудит. Назначение обновляет автора и время изменения назначения.

## Проверки

Backend:

```bash
cd backend
pytest -q -m "not integration"
ruff check .
ruff format --check .
mypy app
```

Браузерные сценарии с реальным API на **отдельной временной SQLite-базе**:

```bash
cd console-tests
npm ci
npx playwright install chromium
npm test
npm run format:check
```

В PowerShell при запрете запуска `.ps1` используйте `npm.cmd` / `npx.cmd`. Для установленного Chrome: `$env:CONSOLE_BROWSER_CHANNEL='chrome'`. Python берётся из корневого `.venv`, либо из PATH; можно задать `CONSOLE_TEST_PYTHON`.

Playwright сам запускает `scripts/run_console_test_server.py` на loopback-порту 18765. Скрипт отключает чтение `.env`, создаёт временную БД и хранилище. Тестовый endpoint сброса существует только внутри этого скрипта; в production-приложении его нет. Не используйте этот тестовый сервер для реальных данных.

Тестируются отказ citizen, права организаций, пагинация, скрытые материалы, жалобы на комментарии, явное объединение, назначение и статусы, публичные ответы, проверка фото и повтор вложения, сохранение формы при ошибке, ротация токенов, XSS и мобильный размер экрана. CI содержит отдельную browser-задачу; миграция также проверяется в существующей PostgreSQL-задаче.

### Результаты локального прогона, 19 октября 2026

- Backend: **60 passed**, 4 интеграционных теста явно исключены; после последней правки сравнения времени повторно прошли все 8 тестов служебной панели.
- Ruff, проверка форматирования Python и mypy: без ошибок.
- Chrome / Playwright с настоящим FastAPI и временной SQLite-базой: **7 passed**. Дополнительно проверен сбой refresh без потери формы.
- Prettier: форматирование JS/HTML/CSS и браузерных тестов проверено.
- Ручной просмотр снимков 1440×1000 и 390×844: горизонтального переполнения нет. [Снимок панели](images/console-moderator.png).
- `alembic upgrade head --sql` успешно генерирует расширение поля до VARCHAR(20). Docker daemon недоступен: фактический запуск Compose, PostgreSQL-миграции и четыре интеграционных теста в этом прогоне не выполнены. CI после отправки изменений должен выполнить отдельный контейнерный прогон.

## Границы этой версии

- Интерфейс панели пока русский. Мобильная RU/KK-локализация сохранена.
- Нет создания организаций и сотрудников, отдельной сетки SLA, массовых операций и уведомлений исполнителю. Имя исполнителя не даёт ему отдельного доступа.
- Нет фонового обновления очереди: после действий она обновляется, также есть ручная кнопка.
- Формы сохраняются при временной ошибке, но не после закрытия/перезагрузки вкладки. Авторизация после перезагрузки повторная.
- Автодетектор лиц/номеров может пропускать объекты; предпросмотр обязателен. Подробнее: [приватность фото](photo-privacy.md).
- Интеграция с государственными системами не имитируется. Принятие означает действие подключённой организации в QalaPulse.

Технические справочники: [Playwright webServer](https://playwright.dev/docs/test-webserver), [нативные диалоги HTML](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).
