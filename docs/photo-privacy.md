# Локальная обработка фотографий

Обновление от 19 октября 2026 года заменяет постоянное размытие всего кадра на скрытие найденных лиц и номеров. Это проверенная на ограниченных контрольных примерах базовая обработка; полевой уровень защиты ещё не подтверждён.

## Как работает

1. Проверяются формат, MIME и размер загружаемого файла.
2. Применяется ориентация EXIF, кадр уменьшается до 1600 px по большей стороне. Исходные метаданные удаляются.
3. OpenCV ищет фронтальные и профильные лица, в том числе зеркальный профиль, и автомобильные номера. Дополнительный геометрический проход ищет светлые таблички с рядом тёмных символов. Отдельные проходы учитывают наклон; координаты возвращаются в систему исходного кадра.
4. К найденным областям добавляется запас: 22% для лиц, 18% для номеров, минимум 4 px. Применяются грубая мозаика и размытие. Остальные пиксели не маскируются; JPEG-перекодирование может немного изменить их значения.
5. Обработанное изображение и миниатюра сохраняются отдельно от оригинала. Оба бакета закрыты, публичную выдачу контролирует API.
6. Flutter показывает полное изображение без обрезки, увеличение до 5× и предупреждения. Подтвердить проверку нельзя до загрузки предпросмотра. Кнопка «Размыть фото целиком» повторно обрабатывает оригинал, сохраняет новый upload ID и снимает прежнее подтверждение. При ошибке запроса черновик сохраняется, проверку нужно подтвердить заново.

Публично выдаются те же байты, которые были показаны в предпросмотре. Оригинал через API предпросмотра или публичного медиа недоступен. После начала публикации с idempotency key изображение в сохранённом запросе не подменяется.

## Настройка и обновление

```env
PRIVACY_MODE=local
```

Обработка работает на CPU без ключей, облака и скачивания моделей во время запроса. Она не зависит от `AI_MODE`. Пакет `opencv-python-headless==4.12.0.88` и NumPy зафиксированы в зависимостях Python 3.13.

Из корня проекта с существующим `.env` и запущенным Docker Desktop:

```bash
docker compose up -d --build backend worker
```

Для консервативного режима установите `PRIVACY_MODE=full_frame` и пересоздайте backend/worker той же командой. Даже в режиме `local` пользователь может запросить полное размытие отдельного фото через multipart-параметр `full_frame=true`. При ошибке загрузки модели или работы детектора оно применяется автоматически. Технический лог содержит только тип ошибки, без пути, фото и распознанного содержимого.

Новые элементы предпросмотра требуют обновления мобильного приложения:

```bash
cd mobile
flutter pub get
flutter gen-l10n
flutter build apk --debug --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/v1
```

Этот URL подходит для Android, подключённого через `adb reverse tcp:8000 tcp:8000`; для другого подключения используйте соответствующий доступный URL backend. См. [запуск на устройстве](development.md).

Миграция БД не требуется. **Уже загруженные фотографии остаются прежними**: обновление не переписывает опубликованные файлы и не восстанавливает детали из размытой копии. Для проверки нового поведения загрузите новое тестовое фото. Повторная обработка старых публикаций должна отдельно предусматривать просмотр результата владельцем или модератором.

## Проверки на контрольных изображениях

Источники: публичный тестовый портрет NASA из scikit-image и собственная синтетическая сцена с автомобилем, вымышленным номером, ямой и переходом. [Происхождение и атрибуция](../backend/tests/fixtures/privacy/README.md). Реальные пользовательские изображения не использовались.

| Проверка | Результат автоматической проверки |
|---|---|
| Лицо: 512×512 и 256×256 | Детектор находит область, маска изменяет детали лица |
| Лицо с наклоном 35° | Маска закрывает более 95% размеченной центральной области |
| Синтетический номер: масштаб 100%, 75%, 50% | Номер обнаруживается, символы мозаицируются |
| Синтетический номер с наклоном 20° | Маска закрывает более 95% размеченной центральной области |
| Яма и переход вне маски | Средняя абсолютная ошибка после JPEG менее 4 из 255 |
| Сцена без номера | Без маски, с предупреждением об ограничениях поиска |
| Сбой детектора / недоступная зависимость | Полное размытие, без выдачи оригинала |
| Права и публикация | Предпросмотр доступен владельцу; публичное фото равно проверенной копии |
| Flutter RU/KK | Ошибка предпросмотра блокирует проверку, повтор работает, черновик сохраняется |

Первоначальная проверка обнаружила пропуски наклонённых лица и номера; добавлены поворотные проходы и регрессионные тесты координат маски. Пиксельные проверки подтверждают применение маски, **но не измеряют вероятность восстановления личности или чтения номера**. Небольшой набор не позволяет заявлять процент точности или полноты обнаружения.

Воспроизведение из активного Python-окружения проекта:

```bash
cd backend
pytest tests/test_selective_privacy.py -q
cd ..
python scripts/check_photo_privacy.py
cd mobile
flutter test test/privacy_preview_test.dart
```

Скрипт создаёт `output/privacy-validation/`: исходники, обработанные JPEG и `report.json` для семи визуальных случаев. Количество найденных областей означает число кандидатов; перекрывающиеся рамки не обязательно являются разными людьми или номерами. Время в отчёте включает два запуска поиска для каждого случая и не является замером задержки upload API. Выходной каталог не коммитится.

## Что проверить до реальных данных

Ограничения базового детектора: маленькие объекты, ночь, блики, грязь, частичное перекрытие, сильная перспектива и нестандартные номера могут приводить к пропускам. Геометрический поиск может закрыть постороннюю прямоугольную надпись. Бейджи, документы, татуировки, отражения и текст с персональными данными автоматически надёжно не определяются. Номерной Haar-каскад не обучен специально на номерах Казахстана. Отсутствие найденных областей не является подтверждением приватности.

Перед реальным пилотом:

1. Собрать постановочные снимки с согласившимися участниками и искусственными номерными табличками: день/ночь, разные телефоны, расстояния, наклоны, несколько людей и автомобилей. Оригиналы держать в закрытом тестовом контуре, не в Git.
2. Разметить все чувствительные области и отдельно саму городскую проблему. Отложить часть снимков для проверки без подстройки детектора под них.
3. Измерить долю пропущенных объектов, неполных масок и ложных масок. Визуально проверить читаемость номеров и узнаваемость лиц с увеличением, а также видимость проблемы.
4. Каждый пропуск разобрать; дополнить регрессионный набор. До приемлемых результатов для условий пилота использовать полное размытие либо ручную модерацию каждого изображения. Не включать реальные данные только на основании прохождения текущих тестов.

Интерфейс `RegionDetector` позволяет заменить базовый OpenCV-поиск более сильной локальной моделью без изменения хранения и API. Автоматическая анонимизация всех чувствительных объектов и сертификация не заявляются.
