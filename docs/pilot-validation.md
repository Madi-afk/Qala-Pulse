## Поведенческие проверки

- Одноразовый сброс пароля и срок действия; одинаковый ответ для отсутствующего/существующего аккаунта; ограничение повторной доставки; отзыв старых access/refresh.
- Одновременные reset/reset и reset/refresh на настоящем PostgreSQL: только один сброс одного токена успешен, новые сессии не переживают завершившийся сброс.
- Закрытая регистрация, отдельный секрет метрик, отсутствие токена в URL после открытия формы, сохранение email при сетевой ошибке.
- Dry-run очистки; удаление оригинала без потери публичного фото; последующее истечение публичной версии; очистка аудио/транскрипта, сиротских файлов и досрочное удаление.
- Backup возобновляет сервисы после ошибки export, не объявляет успех при ошибке и не перезаписывает существующий staging.
- Повреждённые dump/файл и выход пути за каталог backup отклоняются.
- Просроченный файл освобождает мобильный черновик для редактирования, сохраняет текст и GPS.

Во время восстановления найдены и исправлены: конфликт служебных схем PostGIS (используется новая база из `template0`), преждевременная readiness во время init PostgreSQL (проверяется TCP), вложенный read-only mount конфигурации Prometheus. Исправлен запуск integration pytest из каталога backend.

Локальные отчёты: `artifacts/pilot-restore-result.json` и журналы проверок; они не коммитятся. CI сохраняет отчёт восстановления отдельным artifact. Проверки не использовали реальных жителей, их фотографии или почтовые адреса.

## Перед настоящим стартом

На выбранном сервере повторить restore именно из удалённого repository, проверить реальный TLS с телефона, SMTP и доставку alert/resolved, внешний мониторинг вне VPS, расписание systemd, права операторов, реальную подписанную Android/iOS-сборку и [технический допуск](pilot-launch.md). Сроки хранения и контакт поддержки должны быть утверждены владельцем. MFA, полное удаление аккаунта и внешний аудит остаются отдельными задачами.
