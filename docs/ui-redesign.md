# Обновление интерфейса QalaPulse

## Решение

Светлый интерфейс с тёплым фоном, зелёным акцентом и локально встроенным Noto Sans. Карточки обращений остаются главным содержимым; декоративный градиент и крупная иллюстративная иконка из вводного блока убраны.

## Изменения

- Общая тема: палитра, иерархия текста, поля, кнопки, поверхности и навигация.
- Главная: компактный вводный блок, заметная публикация, переход к карте с подходящей подсказкой, приоритетные и последние обращения.
- Карточки: статус с текстом и иконкой, фото либо нейтральный placeholder, дата, отдельные показатели приоритета и подтверждений. Длинные подписи переносятся.
- Детали: тот же компонент статуса, что в ленте.
- Вход и регистрация: новая композиция, доступные подсказки кнопки показа пароля, объявление ошибки для screen reader.
- Профиль: идентификация пользователя, сгруппированные переходы к обращениям и подтверждениям, переключение языка.
- Пустая лента: объяснение следующего действия; на главной есть переход к созданию.
- RU/KK: все новые строки в ARB. Короткая подпись раздела уведомлений в нижней панели — «События» / «Хабарлар»; полный заголовок и tooltip сохранены.
- Noto Sans включён локально, вместе с лицензией OFL. Проверено наличие специфических казахских букв в таблице cmap. Загрузка шрифта из сети не требуется.

Статусы, сохранение черновика, авторизация, работа API, карта и процесс публикации не переписаны. Существующие предупреждения о приватности, mock AI и отсутствии государственной интеграции сохранены.

## Проверки

- `flutter analyze`: без замечаний.
- `dart format --output=none --set-exit-if-changed lib test`: без изменений.
- `flutter test --timeout 30s`: 38 тестов прошли, включая 8 новых.
- `flutter build apk --debug --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/v1`: успешно, APK находится в `mobile/build/app/outputs/flutter-apk/app-debug.apk`.
- Новые проверки: русский и казахский, ширина 390 px и 320 px, масштаб текста до 180%, длинный статус и метаданные при 200%, переход из главной к входу, сохранность email/пароля при смене режима формы, сохранение выбранного языка.
- Снимки реального Flutter-рендеринга главной, ленты, входа и профиля проверены визуально. Для воспроизведения из `mobile`:

```powershell
flutter test test/redesign_test.dart --dart-define=CAPTURE_UI=true --timeout 30s
```

Снимки сохраняются в `mobile/build/redesign/` и не включаются в Git. В снимках используются синтетические данные теста; их нельзя считать проверкой ответа сервера или реальной съёмки камерой.

## Android

Сборка для проверки на телефоне через USB:

```powershell
cd mobile
flutter build apk --debug --dart-define=API_BASE_URL=http://127.0.0.1:8000/api/v1
adb reverse tcp:8000 tcp:8000
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

Backend должен быть запущен на компьютере на порту 8000. На телефоне должны быть включены отладка по USB и разрешение подключения к этому компьютеру. Если `adb` отсутствует в PATH, используйте `& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"` вместо `adb`.

## Границы проверки

Полный сценарий камеры, GPS, микрофона и публикации на физическом телефоне в рамках этого редизайна не выполнялся. Системные диалоги разрешений, клавиатуру и TalkBack следует проверить при приёмке на устройстве. Это debug-сборка для локальной проверки, не подписанный релиз для магазина. Тёмная тема пока не реализована.

При проверке окружения 6 октября 2026 года запрос к `http://127.0.0.1:8000/api/v1/ready` получил отказ в соединении. Успешный запуск backend этим UI-прогоном не подтверждён; перед проверкой телефона запустите инфраструктуру из корня репозитория: `docker compose up -d --build --wait`.

В следующем запросе того же дня Docker восстановлен и backend запущен: readiness PostgreSQL/Redis/MinIO успешно проверен. Подробности — в [local-docker-recovery.md](local-docker-recovery.md).
