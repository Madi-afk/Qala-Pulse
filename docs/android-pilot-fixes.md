## Модель данных и миграция

`0001` не изменена. Новая `0002` добавляет:

- `Incident.resolution_cycle` и `IncidentConfirmation.resolution_cycle`, integer NOT NULL, default 0.
- UNIQUE `(incident_id, user_id, status, resolution_cycle)` вместо прежней тройки.
- `publication_cancellations` с UNIQUE `(user_id, key)` — запреты для отменённых и окончательно отклонённых попыток.

Все прежние ID, комментарии, даты и подтверждения сохраняются в цикле 0. У обращений в `resolved_pending_confirmation`/`resolved` текущий цикл становится 1: старая поддержка не блокирует проверку ремонта после обновления. Существующие счётчики не переписываются; новые оценки уже поддержавшего жителя их не увеличивают. Новый переход в pending увеличивает цикл, повтор того же статуса — нет. Аудит записывает цикл.

На реальном PostgreSQL выполнен тест: создать схему `0001`, внести синтетическую старую запись, применить `0002`, проверить сохранение истории/счётчика. На обычных новых volumes применены обе миграции и seed из 28 обращений. Downgrade отказывается терять историю повторных циклов или запреты ключей. Перед обновлением реальных данных нужны резервная копия и отдельная приёмка; здесь они не затрагивались.

## Команды и результаты

Использованы Python 3.13, Flutter 3.44.1 / Dart 3.12.1. В Windows команды Python запускались через `.venv/Scripts/`; ниже эквиваленты с активным venv.

```bash
cd backend
ruff check .
ruff format --check .
mypy app
python -m pytest -q -m "not integration" --tb=short --show-capture=no
cd ..
python scripts/run_integration.py
cd mobile
flutter gen-l10n
dart run build_runner build
flutter analyze --no-pub
flutter test --timeout 30s
dart format --output=none --set-exit-if-changed lib test
flutter build apk --debug --dart-define=API_BASE_URL=http://10.0.2.2:8000/api/v1
```

Локально: Ruff check/format и mypy прошли; **37 backend unit/API**, **4 реальные integration** и **30 Flutter tests** прошли. Flutter analyze — без замечаний; Dart format — 45 файлов без изменений. Android debug build завершился успешно: `mobile/build/app/outputs/flutter-apk/app-debug.apk` (API для эмулятора `10.0.2.2:8000`). APK не добавлен в Git. В integration остаются предупреждения upstream Starlette/AnyIO deprecation, reflection geography в миграционном тесте и локального Windows pytest cache; они не заменяют и не отключают проверки PostGIS.

Удалённые запуски и статусы отдельных jobs доступны в [Checks draft PR #1](https://github.com/Madi-afk/Qala-Pulse/pull/1/checks). Итоговая ссылка проверенного запуска также указана в отчёте PR. Локальный успешный прогон сам по себе не считается подтверждением GitHub Actions.

Первый [прогон исправлений](https://github.com/Madi-afk/Qala-Pulse/actions/runs/36606489411) подтвердил сборку MinIO, миграции, seed, исходные интеграционные тесты и сохранение миграционных данных; Backend и Flutter прошли. Новый concurrency-тест получил 401 на первом запросе после регистрации. Дополнительный тест воспроизвёл порядок «HTTP response → commit»: клиент мог получить JWT до появления пользователя в другой транзакции. Исправление — `Depends(get_db, scope="function")`, с commit до ответа, по [официальному контракту FastAPI](https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/#early-exit-and-scope). Ошибка не обходится sleep/retry или ослаблением авторизации.

Тестовая конфигурация отключает dotenv-файлы, а Compose runner передаёт сгенерированные параметры поверх унаследованных переменных среды. Исходные настройки пользователя не нужны для проверки.

## Протокол восстановления и ограничения

- После 422 из известного списка бизнес-ошибок сервер фиксирует запрет старого ключа **до** ответа; клиент сохраняет фото, точку, текст и создаёт ключ для исправления. Поздний запрос не сможет опубликовать старый вариант после повторной активации категории.
- При неизвестном исходе повторяются прежние payload/key. «Проверить исход и исправить» вызывает серверную отмену: уже созданное обращение открывается; только подтверждённая отмена позволяет редактировать или удалить черновик. Offline-отмена не объявляется успешной.
- `409` не обрабатывается как разрешение заново отправлять с новым ключом. Коды конфликта ключа/загрузки имеют RU/KK сообщения.
- Карта показывает круговой поиск максимум 20 км и 200 записей, сообщает радиус и переполнение. Изменения других пользователей/операторов появляются при ручном обновлении; push/WebSocket здесь не добавлены.
- MinIO-registry проверенные теги недоступны в этой среде; рабочий вариант — собственная сборка официальных исходников, не новый выдуманный тег. Версии, источники, pull-команды, лицензия и сетевые зависимости описаны в [инфраструктуре](../infrastructure/README.md).

## Непроверенное и ручная приёмка Android

Физический телефон, реальные разрешения ОС/фоновые ограничения, iOS и качество облачного AI в этом этапе не проверены. Сборка APK и widget-тесты не подтверждают эти сценарии. Все следующие пункты — **чек-лист для ручной приёмки**, а не уже выполненные действия:

- [ ] Установить debug APK, указать доступный телефону API; пройти вход на RU и KK.
- [ ] Камера и галерея: выбрать/снять фото; отказать в разрешении и повторно разрешить; проверить публичный preview.
- [ ] GPS: получить точку; запретить GPS и выбрать вручную; выключить службу местоположения и восстановить.
- [ ] Микрофон: запись, прослушивание, отмена, повтор, отказ разрешения; mock-транскрипт редактируется.
- [ ] Офлайн: создать черновик, закрыть/принудительно остановить приложение, открыть — фото/точка/текст сохранены.
- [ ] Потерять ответ публикации после отправки, перезапустить и повторить — на сервере одна запись. Проверить восстановление и отмену при отключённой сети.
- [ ] Отключить выбранную категорию администратором после проверки AI; публикация показывает причину, данные сохраняются, доступно исправление после перезапуска.
- [ ] Отозвать refresh-сессию; следующий 401 показывает вход. Войти другим аккаунтом — чужой черновик отсутствует; исходным — восстановлен.
- [ ] Открыть карту, создать обращение поблизости, вернуться — маркер появился; подтвердить решение — статус обновился; проверить ручной refresh.
- [ ] Переместить карту далеко, нажать «Искать здесь», сменить категорию; при offline показать ошибку и повтор. Проверить ограничение выдачи.
- [ ] Житель поддержал → назначенная организация отметила ремонт → тот же житель оспорил → новый ремонт → житель подтвердил. Счётчик поддержки остаётся прежним, история сохранена; организация получает 403 на confirmation.

Перед приглашением жителей отдельно оценить качество redaction и читаемость проблемы на обработанном фото, приватность пользовательского текста, качество RU/KK AI и эксплуатационные меры пилота из `docs/pilot.md`.
