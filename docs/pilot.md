# Закрытый пилот

Практические инструкции: [сервер и восстановление](pilot-deployment.md), [тестовая группа и модератор](pilot-launch.md), [сроки хранения](photo-retention.md). Сервер, домен и ответственный модератор пока не назначены.

1. Назначить владельца платформы, модераторов и одну реальную организацию, добровольно согласившуюся обрабатывать обращения. Не представлять QalaPulse официальным каналом обращений.
2. Выбрать небольшой район и 20–50 добровольцев. Начать с синтетических фото, затем согласованных несекретных материалов после проверки обработки приватности.
3. Развернуть в контролируемой среде, включить HTTPS, заменить тестовые аккаунты, утвердить контакт и сроки хранения. Провести восстановление из backup.
4. Пройти чек-лист на физических Android/iOS: камера/галерея, отказ GPS, ручная точка, русский/казахский голос, airplane mode, выгрузка приложения, повтор после истёкшего access.
5. В течение 2–4 недель модерировать ежедневно, обсуждать спорные категории и дубликаты, фиксировать ложные срабатывания. Не смешивать demo-данные с пилотной статистикой.

## Метрики

| Метрика | Способ измерения |
|---|---|
| Успешное завершение создания | Начатые пользователями попытки → опубликованные Incident; отдельный учёт отмен |
| Время до публикации | Наблюдаемые сессии, медиана и p95 |
| Правки AI | Доля и тип ручных изменений по согласованной выборке |
| Дубликаты | Precision/recall на размеченной выборке; mock не имеет заявленной точности |
| Потеря черновиков | Принудительный офлайн/перезапуск, ожидается 0 потерь |
| Повторные публикации | Повтор одного idempotency key, ожидается 1 Incident |
| Скорость реакции | published → under_review → accepted/in_progress |
| Реальное устранение | resolved_pending_confirmation → подтверждение/оспаривание жителями |
| Приватность | Проверка public API и изображений, количество инцидентов утечки |

Prometheus предоставляет счётчики HTTP по шаблону маршрута и коду ответа. Продуктовые события пока не отправляются в внешнюю аналитику: дневник пилота и обезличенные SQL-выгрузки остаются под контролем оператора.

## Критерии успешности

Согласовать до старта: ≥90% завершения сценария в наблюдаемых сессиях; 0 потерянных черновиков в контрольных сетевых сбоях; 0 копий для одного ключа; 100% публичных фото проходят redaction; отсутствие несанкционированных изменений. Определить SLA модерации вместе с организацией. Эти значения — цели пилота, а не измеренные результаты.

Собирать обратную связь через короткое интервью после сценария и еженедельную встречу модераторов. Фиксировать версию приложения, ОС, язык, request ID и шаг ошибки; не запрашивать пароль или токен.
